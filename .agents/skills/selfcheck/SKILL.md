# Self-check

実装が、渡された要件および設計を満たしているかレビューする。

要件、設計、検証方法のいずれかが不明確で、妥当な完了判定ができない場合は、推測で判定せずユーザーへ確認する。

## Review scope

次の情報を確認し、今回の検証対象を特定する。

- ユーザーから渡された要件
- Implementation Plan
- ADR
- Design Doc
- `AGENTS.md`
- 現在のGit差分
- 関連する既存コードとテスト
- `package.json`および利用可能なnpm scripts

複数の要件・設計が存在し、どれを基準にすべきか判断できない場合は、検証を始める前にユーザーへ確認する。

## Workflow

1. 要件と設計から、完了条件をチェックリストとして整理する。

2. 現在の実装とテストを調査し、それぞれの完了条件について以下のいずれかに分類する。

   - `Pass`: 完了を確認できた
   - `Fail`: 未完了または要件に違反している
   - `Unknown`: 情報不足により判断できない

3. `Unknown`がある場合は、推測で合格または不合格にせず、必要な情報をユーザーへ確認する。

4. プロジェクトの導入・検証に必要なコマンドが、`package.json`のnpm scriptsとして実行可能であることを確認する。

   既存プロジェクトの構成に応じて、少なくとも以下に相当するコマンドを確認する。

   - セットアップまたは依存関係の導入
   - ビルド
   - lint
   - 型チェック
   - テスト
   - カバレッジ計測

   コマンド名は固定せず、既存の `package.json` とプロジェクト規約を優先する。

   必要な処理がnpm scriptとして定義されていない場合は、未完了として扱う。

5. 利用可能なnpm scriptsを使って検証を実行する。

   例:

   ```bash
   npm run build
   npm run lint
   npm run typecheck
   npm test
   npm run test:coverage
   ```

   実際には `package.json` に定義されているコマンドだけを使用する。存在しないコマンドを推測して実行しない。

6. テストカバレッジが80%以上であることを確認する。

   - リポジトリにカバレッジ閾値の設定がある場合は、その設定を優先する。ただし80%未満の設定は、このself-checkの合格基準を満たさない。
   - Statements、Branches、Functions、Linesが個別に出力される場合は、それぞれの数値を報告する。
   - いずれかの必須指標が80%未満の場合は未完了として扱う。
   - カバレッジを計測できない場合は合格とせず、`Unknown`または`Fail`として理由を報告する。
   - テストを削除、スキップまたは弱体化してカバレッジ要件を満たしてはならない。

7. 既存テストと今回追加・変更されたテストの結果を確認し、デグレードがないことを確認する。

   - テスト失敗を今回の変更と無関係だと推測して無視しない。
   - 既存障害の可能性がある場合は、根拠を示してユーザーへ報告する。
   - 実行できなかった検証がある場合は、その理由を明記する。

## Incomplete work

未完了の項目がある場合は、コードを変更する前に次を提示する。

1. 未完了の項目
2. 要件または設計との差分
3. 考えられる原因
4. 修正対象となるファイル
5. 修正方針
6. 追加または更新するテスト
7. 想定される影響とリスク

修正プランを提示した後、必ずユーザーの合意を得る。

ユーザーから明示的な合意を得るまでは、修正を開始しない。

ユーザーが修正プランに合意しない場合、または合意内容を確定できない場合は、そこで処理を終了する。

## Re-check after fixes

ユーザーの合意を得て修正した場合は、修正後にこのself-checkを最初から再実行する。

再確認では、修正箇所だけでなく以下をすべて確認する。

- 要件および設計への適合
- npm scripts
- ビルド
- lint
- 型チェック
- 全テスト
- カバレッジ
- デグレードの有無

同じ失敗が繰り返され、追加修正の方針を判断できない場合は、推測で修正を続けず、状況をユーザーへ報告して処理を停止する。

## Final report

最後に以下を報告する。

- 総合判定: `Pass`、`Fail`または`Blocked`
- 要件ごとの判定
- 実行したnpm scripts
- テスト結果
- カバレッジ結果
- デグレードの有無
- 実行できなかった検証
- 実施した修正
- 残っている未完了項目

すべての必須条件を確認できた場合のみ、総合判定を `Pass` とする。
